## 发现与处理

| 旧项目证据 | 本次处理 |
|---|---|
| 核心流程分散在 Notebook、脚本与重复切片实现中，部分导入指向缺失模块 | 四个 Python 模块，配置集中，六个命令入口，共享几何函数 |
| 缺失标签可能被当作空标签，切片只留下有目标样本 | 检查图片／标签配对；保留合法空标签和负样本切片 |
| 仅设置 `scale: 0.1` 不能保证小框不缩小，也不能实现内部拼接线过滤 | 实现并测试真正参与训练的数据变换，按目标尺寸约束缩放和裁切 |
| 左右翻转会改变方向标志含义 | 禁用翻转、旋转、MixUp 和二次随机几何变化 |
| 本地评价已有原图预测，但使用逐类 11 点 AP；切片指标与原图指标容易混用 | 独立原图 COCO 101 点评价，记录完整图片清单、类别与数据版本 |
| 原始类别名和旧人工映射存在合并歧义 | 153 类新语义本体、5 类待复核；详见 [类别文档](../ontology.md) 和 [变更清单](ontology-changes.json) |
| MTSD 为全球数据，原标签不能证明欧洲来源 | 默认地域未核实，支持独立图片白名单 |
| 历史训练 CSV 的切片 AP 峰值约 0.62262 出现在第 22 轮；第 35 轮开始到记录结束出现非有限 loss | 不把曲线当成精度上限或硬件故障证明；新训练保存问题批次的图片张量、标签和来源后停止 |
| 恢复训练时框架可能沿用 checkpoint 参数；多 GPU 启动会清理内部运行目录 | 检查恢复配方，只允许设备和 batch 调整；项目记录放在框架 `model/` 目录外 |
| 旧环境与硬编码路径不适合三个运行设备 | 核心轻量安装与训练安装分开；固定训练接口；GPU 配置按机器选用 |

## 类别方案的边界

旧映射为 281 个原始类到 146 类，其余 120 类排除。新映射为 276 个原始类到 153 类、5 类待复核、120 类保留原检测范围的排除；21 个原始 ID 的处理发生改变。新方案并未完成全体 MTSD 标志的视觉与地域审查。

304 原名为 no-stopping，旧本地 `notebook.md` 明确将其调整到 no-parking。阅读这份笔记前曾将其初步判断为直接误合并，完整审查后改为冲突待复核。没有本地图片时，不根据名称覆盖已有人工判断。

本体改动必须从原始 401 类标签重建，无法从已经合并的 146 类标签逆向拆分。含待复核类别的原图整体留出，所以验证结果对应选定子集。120 个排除类不是经过证明的“非欧洲类”。
